# 04. 新增产品或版本接入工作流

**日期**: 2026-05-17  
**状态**: 正式

本文档用于新增同一产品的新版本，或新增全新产品。目标是让不同 Agent 可以按步骤完成目录、导航、版本下拉、侧边栏和验证收口。

## 1. 先判定任务类型

开始前先确认是哪一种：

| 类型 | 示例 | 首页卡片 | 顶部产品入口 | 版本下拉 |
|------|------|----------|--------------|----------|
| 同一产品新版本 | Filament v5.x | 不新增 | 不新增 | 在现有产品下新增版本项 |
| 全新产品 | Laravel 12.x | 新增 | 新增 | 新建该产品自己的版本项 |

不要把同一产品的多个版本做成首页并列卡片。

## 2. 新增同一产品的新版本

以下以 `{product}=filament`、`{version}=v5.x` 为例。实际执行时必须替换变量。

执行命令前可先设置：

```bash
PRODUCT=filament
VERSION=v5.x
LANG=zh-cn
SITE_DOCS="site/docs/$PRODUCT/$VERSION"
SITE_ASSETS="site/static/assets/$PRODUCT/$VERSION"
SIDEBAR_ID="filamentV5Sidebar"
```

### 2.1 建立目录

```text
sources/{product}/{version}/
content/{product}/{version}/zh-cn/docs/
site/docs/{product}/{version}/
site/static/assets/{product}/{version}/
```

如果有官方源码快照，也可以保留上游工作副本：

```text
sources/_upstream/{product}-{version}-docs/
```

`sources/_upstream/` 只作为采集工作区，不是站点构建输入。

### 2.2 准备源文档

优先从官方源码、版本分支或 tag 获取文档：

```text
sources/{product}/{version}/raw/docs/
sources/{product}/{version}/raw-assets/
sources/{product}/{version}/normalized/docs/
sources/{product}/{version}/manifest.yml
```

`manifest.yml` 至少记录：

```yaml
product: filament
version: v5.x
source:
  repo: https://github.com/filamentphp/filament
  ref: 5.x
  docs_path: docs
retrieved_at: YYYY-MM-DD
license: 待确认
```

### 2.3 建立站点页面

每个发布到站点的页面必须同时满足：

- 中文译文归档到 `content/{product}/{version}/zh-cn/docs/...`。
- 可见页面写入 `site/docs/{product}/{version}/...`。
- 图片复制到 `site/static/assets/{product}/{version}/...`。
- 页面中的图片路径使用 `/assets/{product}/{version}/...`。
- 不残留 `raw-assets`、`docs-assets` 或上游框架组件引用。

### 2.4 新增 sidebar

在 `site/sidebars.ts` 中新增独立 sidebar id，例如：

```ts
const sidebars: SidebarsConfig = {
  filamentV5Sidebar: [
    {
      type: 'category',
      label: '介绍',
      collapsed: false,
      items: [
        'filament/v5.x/introduction/overview',
      ],
    },
  ],
};
```

规则：

- 每个产品/版本使用独立 sidebar id。
- 左侧顶层直接是章节分类，不包产品名。
- 文档 ID 等于 `site/docs/` 下路径去掉 `.md`。

### 2.5 更新 docsCatalog

在 `site/src/data/docsCatalog.ts` 的对应产品 `versions` 中追加版本项：

```ts
{
  label: 'v5.x',
  slug: 'v5.x',
  status: '翻译中',
  pages: 'N 个站点页面',
  stage: '接入中',
  docsPath: '/docs/filament/v5.x/introduction/overview',
  docsBasePath: '/docs/filament/v5.x',
  sourceHref: 'https://github.com/filamentphp/filament/tree/5.x/docs',
  sourceLabel: 'Filament v5.x',
  sidebarId: 'filamentV5Sidebar',
}
```

如果新版本应成为默认入口，再修改同一产品的 `defaultVersionSlug`。

### 2.6 检查导航

同一产品新版本完成后，预期效果：

- 首页仍只有一张该产品卡片。
- 产品卡片内出现新版本入口。
- 顶部“版本”下拉出现新版本。
- 点击新版本进入该版本 `docsPath`。
- 左侧栏显示该版本对应 sidebar。

当前实现中，版本下拉跳转到各版本默认入口，不保证保留当前相对页面。

## 3. 新增全新产品

新增全新产品时，需要额外修改：

- `site/src/data/docsCatalog.ts`：新增一个 `DocsProduct`。
- `site/docusaurus.config.ts`：新增对应顶部产品入口和版本下拉策略；当前配置只显式接入 Filament，新增产品时必须扩展这里。
- `site/sidebars.ts`：新增该产品默认版本 sidebar。
- 首页会从 `docsProducts` 自动渲染新产品卡片。

如果新增多个产品，优先抽象 `docusaurus.config.ts` 的 navbar 生成逻辑，避免为每个产品复制硬编码块。

## 4. 链接和占位页策略

当前项目允许构建通过时带有既有 broken links / anchors 警告，但新增版本或产品不应主动扩大未知 404。

执行规则：

- 已经翻译并发布的页面，链接应指向真实页面。
- 尚未接入的页面，不要假设已有占位页。
- 如果需要保留上游链接但站内页面未接入，优先创建明确的“翻译中”占位页，或临时保留外部官方链接。
- 构建后新增的 broken links / anchors 必须说明来源和处理计划。

## 5. 验证命令

从 `site/` 目录执行：

```bash
npm run typecheck
npm run build
```

从仓库根目录执行：

```bash
grep -rn "raw-assets\|docs-assets" "$SITE_DOCS/"
grep -rn "@components\|AutoScreenshot\|<Aside\|<Disclosure\|<RadioGroup\|<UtilityInjection" "$SITE_DOCS/"
```

页面访问验证：

- 不自动执行 `npm run start`。
- 如果用户已有 dev server，提示用户刷新页面。
- 如果用户明确要求启动服务，再从 `site/` 运行 `npm run start`。

## 6. 完成后同步文档

新增产品或版本后，同步：

- `docs/README.md`
- `docs/01_项目规划与设计/04_目录结构详解.md`
- 必要时补 `docs/03_开发历史记录/NN_主题开发记录.md`

历史记录保持简短，写清需求背景、实现要点、验证结果和后续注意点。
