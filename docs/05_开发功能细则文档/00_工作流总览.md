# 00. 工作流总览

**日期**: 2026-05-17  
**状态**: 正式

本文档是 `docs/05_开发功能细则文档/` 的入口。任何 Agent 在进行文档采集、翻译、新版本接入、校对、代码注释增强或本地化超链接适配前，应先阅读本文件，再进入对应流程。

## 1. 工作流地图

| 任务 | 主要阅读文档 | 产出 |
|------|-------------|------|
| 新增同一产品的新版本，例如 Filament v5.x | `04_新增产品或版本接入工作流.md` | 新版本目录、sidebar、`docsCatalog` 版本项、可访问入口 |
| 新增全新产品，例如 Laravel | `04_新增产品或版本接入工作流.md` | 新产品目录、首页产品卡片、navbar 产品入口、版本下拉项 |
| 翻译或补齐单篇文档 | `02_翻译操作指南.md` | `content/` 归档译文和 `site/docs/` 站点页面 |
| 批量校对译文 | `03_翻译校对工作流.md` | 校对结论、修复项、构建验证结果 |
| 为已校对文档中的示例代码补充中文注释 | `05_代码注释增强工作流.md` | 高密度中文代码注释、`content/` 与 `site/docs/` 同步、注释增强报告 |

## 2. 路径变量

流程文档默认使用这些变量。执行任务时先把变量替换为具体值，不要直接复制示例中的 `v4.x`。

| 变量 | 示例 | 含义 |
|------|------|------|
| `{product}` | `filament` | 产品目录名，使用小写短横线或现有目录风格 |
| `{version}` | `v4.x` | 站内版本目录名 |
| `{lang}` | `zh-cn` | 翻译语言目录 |
| `{source_docs}` | `sources/filament/v4.x/normalized/docs` | 清洗后的英文源文件目录 |
| `{content_docs}` | `content/filament/v4.x/zh-cn/docs` | 中文翻译归档目录 |
| `{site_docs}` | `site/docs/filament/v4.x` | Docusaurus 实际读取的文档目录 |
| `{site_assets}` | `site/static/assets/filament/v4.x` | Docusaurus 静态资源目录 |
| `{sidebar_id}` | `filamentV4Sidebar` | 当前产品/版本对应的 sidebar id |

## 3. 当前导航模型

- 首页按产品/框架聚合入口，例如一张 `Filament` 卡片。
- 同一产品的多个版本通过顶部“版本”下拉和产品卡片内版本入口切换。
- 文档路径保留版本段，例如 `/docs/filament/v4.x/introduction/overview`。
- 当前版本下拉使用 Docusaurus 内置 `dropdown`，点击版本会进入该版本默认入口。
- 产品、版本、默认入口、来源链接和 sidebar id 集中维护在 `site/src/data/docsCatalog.ts`。

## 4. 执行原则

- 先确认任务类型，再读对应流程；不要只凭文件名猜状态。
- 处理 Filament v4.x 时，先读 `源文件结构详解/Filament_v4x_官方GitHub源文件结构详解.md`；处理 Livewire v3.x 时，先读 `源文件结构详解/Livewire_v3x_官方GitHub源文件结构详解.md`；其他框架或版本必须重新联网核对，不复用既有结构说明。
- 已校对文档需要增强示例代码可读性时，按 `05_代码注释增强工作流.md` 对照英文源文和中文译文添加中文注释。
- 修复站内链接时，按 `06_本地化超链接适配工作流.md` 先核对本地真实页面和锚点，再同步修改 `content/` 与 `site/docs/`。
- `sources/` 是原文和清洗结果，不是译文输出目录。
- `content/` 是中文翻译归档，不直接被站点读取；归档路径应与官网 URL 结构一致。
- `site/docs/` 是用户实际看到的内容，路径应与官网 URL 结构一致。
- 新增可见页面必须同步 `site/sidebars.ts`。
- 新增产品或版本必须同步 `site/src/data/docsCatalog.ts`。
- 同一产品的新版本不新增首页并列产品卡片。
- 修改站点结构后优先运行 `npm run typecheck` 和 `npm run build`。
- 不自动启动 `npm run start`；通常用户已有服务运行，完成后提示用户刷新页面。

## 5. 最小验收清单

任何流程完成后，至少确认：

- [ ] 目录写入位置正确，没有把新版本内容写进旧版本目录。
- [ ] `content/` 和 `site/docs/` 同步。
- [ ] 图片路径已转换为 `/assets/{product}/{version}/...`。
- [ ] `site/sidebars.ts` 已注册新增页面或新版本 sidebar。
- [ ] `site/src/data/docsCatalog.ts` 已同步产品/版本入口。
- [ ] `npm run typecheck` 通过。
- [ ] `npm run build` 通过；如果有 broken links / anchors，已确认是既有或本阶段可接受问题。
- [ ] 已提示用户刷新已有页面，而不是自行启动 dev server。
