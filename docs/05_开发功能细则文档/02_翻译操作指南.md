# 02. 翻译操作指南

**日期**: 2026-05-16  
**最近更新**: 2026-05-18  
**状态**: 正式

本文档定义单篇或少量文档的翻译、归档、入站和验证流程。新增产品或新增版本时，先执行 `04_新增产品或版本接入工作流.md`，再回到本文档处理具体页面。

## 0. 执行前确认

先确定这些变量：

| 变量 | 示例 | 说明 |
|------|------|------|
| `{product}` | `filament` | 产品目录名 |
| `{version}` | `v4.x` | 版本目录名 |
| `{lang}` | `zh-cn` | 译文语言 |
| `{source_file}` | `sources/filament/v4.x/normalized/docs/01-introduction/01-overview.md` | 英文源文件 |
| `{content_file}` | `content/filament/v4.x/zh-cn/docs/introduction/overview.md` | 中文归档文件，按官网 URL 结构保存 |
| `{site_file}` | `site/docs/filament/v4.x/introduction/overview.md` | 站点可见文件 |
| `{asset_prefix}` | `/assets/filament/v4.x/` | 站点图片绝对路径前缀 |
| `{sidebar_id}` | `filamentV4Sidebar` | 当前产品/版本 sidebar id |

确认后再动手：

```bash
PRODUCT=filament
VERSION=v4.x
LANG=zh-cn
SOURCE_FILE="sources/$PRODUCT/$VERSION/normalized/docs/01-introduction/01-overview.md"
CONTENT_FILE="content/$PRODUCT/$VERSION/$LANG/docs/introduction/overview.md"
SITE_FILE="site/docs/$PRODUCT/$VERSION/introduction/overview.md"
SITE_DOCS="site/docs/$PRODUCT/$VERSION"
ASSET_PREFIX="/assets/$PRODUCT/$VERSION"
SIDEBAR_ID="filamentV4Sidebar"
```

- [ ] 目标产品和版本已在 `site/src/data/docsCatalog.ts` 中登记。
- [ ] 目标产品/版本已有对应 `site/sidebars.ts` sidebar。
- [ ] 源文件来自 `sources/{product}/{version}/normalized/docs/` 或明确记录的上游源。
- [ ] 不把新版本内容写进旧版本目录。

路径分工：

- `sources/` 可以保留 GitHub 官方源文件结构，例如 `01-introduction/01-overview.md`。
- `content/` 保存中文翻译归档，应采用官网 URL 结构，例如 `introduction/overview.md`。
- `site/docs/` 发布到 Docusaurus，也采用官网 URL 结构。

## 1. 链接处理规则

内部链接需要优先指向当前产品和当前版本。

已接入站点的页面，应指向真实页面：

```markdown
# 错误：指向目录但目录没有 index 页面
[资源文档](resources)

# 正确：指向具体文档
[资源文档](resources/overview)
```

尚未接入的站内页面，不要假设已有占位页。可选处理：

- 如果本轮需要该链接可用，创建明确的“翻译中”占位页，并加入 `site/sidebars.ts`。
- 如果暂不接入，保留官方外部链接或在本轮记录为已知 broken link。
- 不要把链接指向 `sources/` 或 `content/`。

外部链接保持原始 URL：

```markdown
[Livewire 组件](https://livewire.laravel.com/docs/components)
```

## 2. 单篇翻译流程

### 步骤 1：读取源文件

```bash
sed -n '1,220p' "$SOURCE_FILE"
```

不要只看文件名、大小或行数判断是否已翻译。必须读取正文。

### 步骤 2：翻译内容

翻译时遵守：

- 保留 Markdown 结构、frontmatter 意图、标题层级、表格、列表和 admonition。
- 代码块默认不翻译。
- 类名、方法名、配置键、命令、文件路径和 URL 不翻译。
- 技术术语优先沿用同产品已有译法。
- 图片路径可以先保留原样，入站到 `site/docs/` 时统一转换。

### 步骤 3：保存到 content 归档

```bash
mkdir -p "$(dirname "$CONTENT_FILE")"
# 将中文译文写入 "$CONTENT_FILE"
```

`content/` 是翻译成果归档，不直接被 Docusaurus 读取。

### 步骤 4：发布到 site/docs

```bash
mkdir -p "$(dirname "$SITE_FILE")"
cp "$CONTENT_FILE" "$SITE_FILE"
```

发布后必须修复图片路径、组件语法和 sidebar。

## 3. 图片路径转换

站点中的图片必须使用绝对路径：

```text
/assets/{product}/{version}/...
```

常见转换：

| 源文件路径 | 站点路径 |
|-----------|----------|
| `../../raw-assets/docs-assets/screenshots/...` | `/assets/{product}/{version}/screenshots/...` |
| `../../../raw-assets/docs-assets/screenshots/...` | `/assets/{product}/{version}/screenshots/...` |

批量替换示例：

```bash
sed -i "s|../../raw-assets/docs-assets/|$ASSET_PREFIX/|g" "$SITE_FILE"
sed -i "s|../../../raw-assets/docs-assets/|$ASSET_PREFIX/|g" "$SITE_FILE"
```

检查残留：

```bash
grep -n "raw-assets\|docs-assets" "$SITE_FILE"
```

有输出就继续修，不要进入下一步。

## 4. 上游组件转换

上游文档可能使用 Astro 或其他文档框架组件。Docusaurus 不支持这些组件，必须转换。

Filament 常见示例：

```markdown
import AutoScreenshot from "@components/AutoScreenshot.astro"
<AutoScreenshot name="panels/resources/creating" alt="创建页面" version="4.x" />
```

转换为：

```markdown
![创建页面](/assets/{product}/{version}/screenshots/images/light/panels/resources/creating.jpg)
```

转换规则：

- 删除 `import ... from "@components/..."`。
- `<AutoScreenshot name="X" alt="Y" version="..." />` 转为 `![Y](/assets/{product}/{version}/screenshots/images/light/X.jpg)`。
- `Aside` 转为 Docusaurus admonition，例如 `:::info`、`:::tip`、`:::warning`、`:::danger`。
- `Disclosure` 可按内容复杂度转为 `<details>` 或普通段落。
- `RadioGroup`、`UtilityInjection` 等交互组件改为线性文档说明。

检查命令：

```bash
grep -n "@components\|AutoScreenshot\|<Aside\|<Disclosure\|<RadioGroup\|<UtilityInjection" "$SITE_FILE"
```

## 5. 图片文件复制

如果页面引用图片，确认图片文件存在：

```bash
grep -oP '!\[.*?\]\(\K[^)]+' "$SITE_FILE" | while read path; do
  case "$path" in
    /assets/*)
      [ -f "site/static${path}" ] || echo "MISSING: ${path}"
      ;;
  esac
done
```

如果缺失，从 `sources/{product}/{version}/raw-assets/` 或明确记录的 `sources/_upstream/...` 复制到：

```text
site/static/assets/{product}/{version}/...
```

不要热链官方图片。

## 6. Frontmatter 要求

每篇站点文档至少应有可读标题：

```yaml
---
title: 创建记录
---
```

规则：

- `title` 通常翻译为中文。
- 不给普通标题加多余引号。
- 原文已有关键 frontmatter 时保留其意图。
- 如果项目后续统一添加来源和翻译状态字段，应在 `content/` 和 `site/docs/` 保持一致。

## 7. 侧边栏注册

新增可见页面必须注册到 `site/sidebars.ts`。Docusaurus 不会自动把新文件加入侧边栏。

文档 ID 规则：

```text
site/docs/{product}/{version}/resources/creating-records.md
-> {product}/{version}/resources/creating-records
```

示例：

```ts
const sidebars: SidebarsConfig = {
  filamentV4Sidebar: [
    {
      type: 'category',
      label: '资源',
      items: [
        'filament/v4.x/resources/overview',
        'filament/v4.x/resources/creating-records',
      ],
    },
  ],
};
```

规则：

- 添加到正确的 `{sidebar_id}`。
- 左侧顶层仍是章节分类，不添加产品名外层分类。
- 同一分类内按官方阅读顺序排列。

## 8. docsCatalog 同步

翻译普通页面通常不需要修改 `site/src/data/docsCatalog.ts`。

以下情况必须修改：

- 新增产品。
- 新增版本。
- 调整某个版本默认入口。
- 修改版本状态、页面数量、来源链接或阶段说明。

修改后检查：

- 首页产品卡片显示正确版本。
- 顶部“版本”下拉显示正确版本。
- 点击版本进入该版本默认入口。

## 9. 验证清单

从仓库根目录检查：

```bash
grep -rn "raw-assets\|docs-assets" "$SITE_DOCS/"
grep -rn "@components\|AutoScreenshot\|<Aside\|<Disclosure\|<RadioGroup\|<UtilityInjection" "$SITE_DOCS/"
```

从 `site/` 目录检查：

```bash
npm run typecheck
npm run build
```

构建结果判断：

- `Module not found`、`MDX compilation failed`、图片缺失等是阻断问题，必须修。
- broken links / anchors 如果是既有未接入页面，可以记录为已知问题；如果是本轮新增，需要修或说明处理计划。

页面验证：

- 不自动启动 `npm run start`。
- 如果用户已有本地服务，完成后提示用户刷新对应页面。
- 如果用户明确要求启动服务，才从 `site/` 执行 `npm run start`。

## 10. 完成标准

一篇文档完成入站时，应满足：

- [ ] `{content_file}` 已保存中文译文。
- [ ] `{site_file}` 已更新为用户可见内容。
- [ ] 图片路径全部为 `/assets/{product}/{version}/...`。
- [ ] 引用图片存在于 `site/static/assets/{product}/{version}/...`。
- [ ] 不残留上游框架组件。
- [ ] 新增页面已加入正确 sidebar。
- [ ] `npm run typecheck` 通过。
- [ ] `npm run build` 通过或仅存在已记录的非阻断警告。
