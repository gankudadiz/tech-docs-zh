# 02. 翻译操作指南

**日期**: 2026-05-16
**最近更新**: 2026-05-17
**状态**: 正式

本文档详细说明如何正确翻译文档并部署到站点，避免常见错误。

## 0. 链接处理规则

翻译文档时，内部链接需要特别注意：

### 已翻译文档的链接

确保链接指向正确的路径：

```markdown
# 错误：指向目录
[资源文档](resources)

# 正确：指向具体文档
[资源文档](resources/overview)
```

### 尚未翻译的文档

对于尚未翻译的文档，站点中已有占位页面，链接可以正常指向：

```markdown
# 这些链接会指向占位页面，显示"翻译中"
[表单](../forms)
[表格](../tables)
[导航](../navigation)
```

### 外部链接

外部链接保持原样即可：

```markdown
[Livewire 组件](https://livewire.laravel.com/docs/components)
```

## 1. 翻译前准备

### 1.1 确认源文件位置

源文件位于 `sources/filament/v4.x/normalized/docs/` 目录。

```bash
# 查看可用的源文件
find sources/filament/v4.x/normalized/docs -name "*.md" -type f
```

### 1.2 理解路径差异

| 目录 | 图片路径格式 | 用途 |
|------|-------------|------|
| `sources/.../normalized/` | 相对路径 `../../raw-assets/...` | 源文件，用于翻译参考 |
| `site/docs/` | 绝对路径 `/assets/filament/v4.x/...` | 站点文件，用户可见 |

**这是最容易出错的地方！** 翻译时必须转换图片路径。

## 2. 翻译流程

### 步骤 1：读取源文件

```bash
# 示例：读取 overview.md
cat sources/filament/v4.x/normalized/docs/01-introduction/01-overview.md
```

### 步骤 2：翻译内容

翻译时注意：
- 保留所有 Markdown 格式
- 代码块不翻译
- 技术术语保持一致（参考术语表）
- 图片路径**先保留原样**，后续统一处理

### 步骤 3：存储翻译成果（归档）

将翻译后的内容保存到 `content/` 目录：

```bash
# 创建目录结构
mkdir -p content/filament/v4.x/zh-cn/docs/01-introduction

# 保存翻译文件
# content/filament/v4.x/zh-cn/docs/01-introduction/01-overview.md
```

### 步骤 4：部署到站点（关键步骤！）

**必须执行以下操作：**

1. 复制文件到 `site/docs/`
2. 修复图片路径

```bash
# 1. 复制文件
cp content/filament/v4.x/zh-cn/docs/01-introduction/01-overview.md \
   site/docs/filament/v4.x/introduction/overview.md

# 2. 修复图片路径
# 将 ../../raw-assets/docs-assets/ 替换为 /assets/filament/v4.x/
# 将 ../../../raw-assets/docs-assets/ 替换为 /assets/filament/v4.x/
```

## 3. 图片路径转换规则详解

### 3.1 路径对照表

| 源文件中的路径 | 站点中正确的路径 |
|--------------|----------------|
| `../../raw-assets/docs-assets/screenshots/images/light/panels/dashboard.jpg` | `/assets/filament/v4.x/screenshots/images/light/panels/dashboard.jpg` |
| `../../../raw-assets/docs-assets/screenshots/images/light/panels/resources/listing.jpg` | `/assets/filament/v4.x/screenshots/images/light/panels/resources/listing.jpg` |

### 3.2 转换逻辑

```
原始：../../raw-assets/docs-assets/screenshots/...
转换：/assets/filament/v4.x/screenshots/...

规则：
1. 去掉所有 ../ 前缀
2. 去掉 raw-assets/docs-assets/ 层级
3. 添加 /assets/filament/v4.x/ 前缀
4. 使用绝对路径（以 / 开头）
```

### 3.3 批量转换命令

```bash
# 对单个文件进行路径转换
sed -i 's|\.\./\.\./raw-assets/docs-assets/|/assets/filament/v4.x/|g' site/docs/filament/v4.x/introduction/overview.md
sed -i 's|\.\./\.\./\.\./raw-assets/docs-assets/|/assets/filament/v4.x/|g' site/docs/filament/v4.x/introduction/overview.md

# 对目录下所有文件进行批量转换
find site/docs/filament/v4.x -name "*.md" -exec \
  sed -i 's|\.\./\.\./raw-assets/docs-assets/|/assets/filament/v4.x/|g' {} \;
find site/docs/filament/v4.x -name "*.md" -exec \
  sed -i 's|\.\./\.\./\.\./raw-assets/docs-assets/|/assets/filament/v4.x/|g' {} \;
```

## 4. 完整翻译示例

以翻译 `01-introduction/01-overview.md` 为例：

```bash
# 1. 读取源文件
cat sources/filament/v4.x/normalized/docs/01-introduction/01-overview.md

# 2. 进行翻译（在编辑器或 AI 工具中完成）

# 3. 保存翻译成果到 content/
# 文件：content/filament/v4.x/zh-cn/docs/01-introduction/01-overview.md

# 4. 复制到站点目录
cp content/filament/v4.x/zh-cn/docs/01-introduction/01-overview.md \
   site/docs/filament/v4.x/introduction/overview.md

# 5. 修复图片路径
sed -i 's|\.\./\.\./raw-assets/docs-assets/|/assets/filament/v4.x/|g' \
  site/docs/filament/v4.x/introduction/overview.md

# 6. 验证路径是否正确
grep -n "raw-assets" site/docs/filament/v4.x/introduction/overview.md
# 应该没有输出，表示所有路径都已修复

# 7. 检查站点是否正常
# 访问 http://127.0.0.1:48763/docs/filament/v4.x/introduction/overview
```

## 5. 验证清单

翻译完成后，逐项检查：

- [ ] 文件已复制到 `site/docs/filament/v4.x/` 对应位置
- [ ] 图片路径已从相对路径转换为绝对路径
- [ ] 没有残留的 `raw-assets` 路径（用 grep 检查）
- [ ] 没有残留的 Astro 组件（`@components`、`AutoScreenshot`、`Aside` 等）
- [ ] 引用的图片文件已复制到 `site/static/assets/` 对应目录
- [ ] 页面能正常加载，图片显示正常
- [ ] 代码块未被误翻译
- [ ] 内链指向正确的站内路径
- [ ] **已在 `site/sidebars.ts` 的正确产品/版本侧边栏中添加条目**（新增文档必做）
- [ ] 翻译成果已归档到 `content/` 目录

## 6. 侧边栏配置（新增文档必做）

Docusaurus 的侧边栏是**手动配置**的，不会自动扫描文件系统。新增文档后必须在 `site/sidebars.ts` 中注册，否则侧边栏中看不到。

当前项目约定：侧边栏按产品/版本隔离。左侧边栏只显示当前产品/版本的章节目录，不再包一层站点级或产品级总入口。

### 6.1 sidebars.ts 结构

```typescript
const sidebars: SidebarsConfig = {
  filamentV4Sidebar: [
    {
      type: 'category',
      label: '介绍',          // 分类名称
      collapsed: false,
      items: [
        'filament/v4.x/introduction/overview',       // 文档 ID = 文件相对路径（去掉 .md）
        'filament/v4.x/introduction/installation',
        'filament/v4.x/getting-started',
      ],
    },
    {
      type: 'category',
      label: '资源',
      collapsed: false,
      items: [
        'filament/v4.x/resources/overview',
        'filament/v4.x/resources/listing-records',
        // 新增文档在这里添加...
      ],
    },
    // ... 其他分类
  ],
};
```

结构规则：

- `filamentV4Sidebar` 代表 Filament v4.x 这一套文档。
- 侧边栏顶层直接是章节分类，例如 `介绍`、`资源`、`组件`。
- 不要在侧边栏中新增 `中文技术文档站`、`文档` 或 `Filament v4.x` 外层分类。
- 后续新增 Laravel 等产品时，新建对应 sidebar id 和 navbar/homepage 入口，不要追加到 `filamentV4Sidebar`。

### 6.2 文档 ID 规则

文档 ID = 文件相对于 `site/docs/` 的路径，去掉 `.md` 扩展名：

| 文件路径 | 文档 ID |
|---------|---------|
| `site/docs/filament/v4.x/introduction/overview.md` | `filament/v4.x/introduction/overview` |
| `site/docs/filament/v4.x/resources/creating-records.md` | `filament/v4.x/resources/creating-records` |

### 6.3 新增文档操作步骤

以新增 `03-resources/03-creating-records.md` 为例：

```bash
# 1. 复制翻译文件到 site/docs/
cp content/filament/v4.x/zh-cn/docs/03-resources/03-creating-records.md \
   site/docs/filament/v4.x/resources/creating-records.md

# 2. 修复图片路径（如有）
sed -i 's|\.\./\.\./raw-assets/docs-assets/|/assets/filament/v4.x/|g' \
  site/docs/filament/v4.x/resources/creating-records.md

# 3. 编辑 site/sidebars.ts，在对应产品/版本侧边栏的对应分类中添加：
#    'filament/v4.x/resources/creating-records',
```

### 6.4 注意事项

- 侧边栏的**顺序**由 `items` 数组中的顺序决定，与文件系统无关
- `collapsed: false` 表示默认展开该分类
- 侧边栏标签文字来自文档 frontmatter 中的 `title` 字段
- 同一个分类下的文档会在侧边栏中按数组顺序排列
- 新增产品或版本时，先建立独立 sidebar id，再接入顶部导航和首页入口

## 7. 图片资源处理（完整流程）

### 7.1 问题背景

上游 Filament 文档使用 Astro 框架，图片通过 `AutoScreenshot` 组件引用：

```markdown
import AutoScreenshot from "@components/AutoScreenshot.astro"
<AutoScreenshot name="panels/resources/creating" alt="创建页面" version="4.x" />
```

**Docusaurus 不支持 Astro 组件**，必须转换为标准 Markdown 图片语法。

### 7.2 图片资源位置

| 位置 | 说明 |
|------|------|
| `sources/_upstream/filament-4.x-docs/docs-assets/screenshots/images/light/...` | 上游源码中的图片文件 |
| `site/static/assets/filament/v4.x/screenshots/images/light/...` | 站点静态资源目录（构建时使用） |

**图片文件必须复制到 `site/static/` 目录才能在站点中显示。**

### 7.3 完整处理流程

翻译含图片的文档时，按以下步骤操作：

**第一步：识别图片引用**

检查源文件中是否有 Astro 组件引用：
```bash
grep -n "AutoScreenshot\|@components" sources/filament/v4.x/raw/docs/03-resources/03-creating-records.md
```

**第二步：转换为标准 Markdown**

将 Astro 组件转换为 Markdown 图片语法：

```markdown
# 转换前（Astro 组件）
import AutoScreenshot from "@components/AutoScreenshot.astro"
<AutoScreenshot name="panels/resources/creating" alt="创建页面" version="4.x" />

# 转换后（标准 Markdown）
![创建页面](/assets/filament/v4.x/screenshots/images/light/panels/resources/creating.jpg)
```

转换规则：
- 去掉 `import` 行
- `<AutoScreenshot name="X" alt="Y" version="4.x" />` → `![Y](/assets/filament/v4.x/screenshots/images/light/X.jpg)`
- 注意：`name` 属性值直接拼接到路径中，`version` 不参与路径

**第三步：复制图片文件到 static 目录**

```bash
# 查找上游源码中的图片
find sources/_upstream/filament-4.x-docs/docs-assets/screenshots/images/light/ -name "creating*.jpg"

# 复制到站点静态目录
cp sources/_upstream/filament-4.x-docs/docs-assets/screenshots/images/light/panels/resources/creating.jpg \
   site/static/assets/filament/v4.x/screenshots/images/light/panels/resources/
```

**第四步：验证图片存在**

```bash
# 检查所有引用的图片是否都存在于 static 目录
# 提取 markdown 中的图片路径
grep -oP '!\[.*?\]\(\K[^)]+' site/docs/filament/v4.x/resources/creating-records.md | while read path; do
  [ -f "site/static${path}" ] && echo "OK: $path" || echo "MISSING: $path"
done
```

### 7.4 源文件中的相对路径图片

除了 Astro 组件，源文件中也可能使用标准 Markdown 相对路径引用图片：

```markdown
# 源文件中的相对路径
![资源列表页](../../raw-assets/docs-assets/screenshots/images/light/panels/resources/listing.jpg)

# 转换为站点绝对路径
![资源列表页](/assets/filament/v4.x/screenshots/images/light/panels/resources/listing.jpg)
```

转换规则同第 3 节。

## 8. 常见问题

### Q: 为什么图片加载失败？

A: 最可能的原因是图片路径没有从相对路径转换为绝对路径。检查是否还有 `raw-assets` 残留。

```bash
grep -r "raw-assets" site/docs/filament/v4.x/
```

### Q: 编译报错 `Can't resolve '@components/AutoScreenshot.astro'`？

A: 源文件使用了 Astro 组件，需要转换为标准 Markdown 图片语法，并确保图片文件已复制到 `site/static/`。参见第 7 节"图片资源处理"。

### Q: 新增的文档在侧边栏中看不到？

A: 侧边栏是手动配置的，必须在 `site/sidebars.ts` 对应产品/版本的 sidebar 中添加文档 ID。参见第 6 节"侧边栏配置"。

### Q: 为什么 content/ 和 site/docs/ 内容不一致？

A: `content/` 是归档，`site/docs/` 是站点实际读取的目录。翻译后需要手动复制并修复路径。

### Q: 新增文档文件时需要注意什么？

A: 确保：
1. 在 `site/docs/` 中创建对应的目录结构
2. 在 `site/sidebars.ts` 的正确产品/版本 sidebar 中添加配置（**必须，否则侧边栏不会显示**）
3. 图片使用绝对路径 `/assets/filament/v4.x/...`
4. 图片文件已复制到 `site/static/assets/` 对应目录
