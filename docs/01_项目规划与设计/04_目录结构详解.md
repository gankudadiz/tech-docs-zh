# 04. 目录结构详解

**日期**: 2026-05-16
**最近更新**: 2026-05-17
**状态**: 正式

## 1. 项目定位

**项目名称**：中文技术文档站

**核心定位**：收录常用开发框架的官方文档中文翻译版本，提供本地优先的阅读体验。

**支持的产品和版本**：
- Filament (v3.x, v4.x, v5.x, ...)
- Laravel (10.x, 11.x, 12.x, ...)
- Livewire (v2.x, v3.x, ...)
- Alpine.js
- Tailwind CSS
- 其他常用开发框架

## 2. 顶层目录概览

```text
tech-docs-zh/
├── docs/           # 项目自身的规划、设计、历史文档
├── sources/        # 官方原文采集快照（只读参考）
├── content/        # 翻译后的文档存储（翻译成果归档）
├── site/           # Docusaurus 文档站（实际运行的站点）
├── scripts/        # 采集、转换、校验脚本（待建设）
└── plan/           # Claude Code 生成的计划文件
```

## 3. 各目录详细说明

### 2.1 `docs/` - 项目文档

项目自身的文档，与翻译内容无关。

```text
docs/
├── README.md                           # 文档索引
├── 01_项目规划与设计/
│   ├── 01_项目草案.md
│   ├── 02_技术栈与架构决策.md
│   ├── 03_UI设计标准.md
│   └── 04_目录结构详解.md              # 本文件
├── 02_运维与部署/
│   └── 01_本地开发环境约定.md
├── 03_开发历史记录/
│   ├── 01_项目初始化开发记录.md
│   ├── 02_Filament_v4x_样板接入记录.md
│   ├── 03_Filament_v4x_首轮翻译记录.md
│   ├── 04_Filament_v4x_侧边栏结构调整记录.md
│   └── 05_框架入口与版本下拉调整记录.md
└── 05_开发功能细则文档/
```

### 2.2 `sources/` - 原文采集

从官方仓库采集的原始文档快照，**只用于参考，不直接用于站点构建**。

```text
sources/
└── filament/
    └── v4.x/
        ├── manifest.yml                # 来源、版本、commit、许可信息
        ├── raw/                        # 官方原文快照（完整目录结构）
        │   └── docs/
        │       ├── 01-introduction/
        │       ├── 02-getting-started.md
        │       ├── 03-resources/
        │       └── ...
        ├── raw-assets/                 # 官方图片等静态资源
        │   └── docs-assets/
        │       └── screenshots/
        └── normalized/                 # 清洗后的可翻译文档
            └── docs/
                ├── 01-introduction/
                ├── 02-getting-started.md
                └── 03-resources/
```

**重要说明**：
- `normalized/` 中的图片路径是相对路径（如 `../../raw-assets/...`），这是为了在 `sources/` 目录内可以预览
- 这些路径**不能直接复制到 `site/docs/`**，需要转换

### 2.3 `content/` - 翻译成果归档

翻译后的文档存储，**用于归档和版本管理，不直接用于站点构建**。

```text
content/
├── README.md
└── filament/
    └── v4.x/
        └── zh-cn/
            └── docs/
                ├── 01-introduction/
                │   ├── 01-overview.md
                │   └── 02-installation.md
                ├── 02-getting-started.md
                └── 03-resources/
                    ├── 01-overview.md
                    └── 02-listing-records.md
```

**重要说明**：
- `content/` 是翻译成果的归档位置
- 翻译完成后，需要将内容复制到 `site/docs/` 才能生效
- 复制时需要修复图片路径

### 2.4 `site/` - Docusaurus 文档站

**实际运行的站点，用户看到的内容来自这里**。

```text
site/
├── docs/                               # ← 站点实际读取的文档目录
│   ├── intro.md                        # Docusaurus docs 根页，不进入产品版本侧边栏
│   └── filament/
│       └── v4.x/
│           ├── introduction/
│           │   ├── overview.md         # ← 这里的内容才是用户看到的
│           │   └── installation.md
│           ├── getting-started.md
│           └── resources/
│               ├── overview.md
│               └── listing-records.md
├── static/                             # 静态资源目录
│   └── assets/
│       └── filament/
│           └── v4.x/
│               └── screenshots/        # ← 图片实际存放位置
│                   └── images/
│                       └── light/
│                           └── panels/
├── src/                                # 自定义组件、页面、样式和文档目录数据
│   ├── data/
│   │   └── docsCatalog.ts              # 产品、版本、默认入口和来源配置
│   └── pages/
│       └── index.tsx                   # 首页按产品/框架聚合展示
├── docusaurus.config.ts                # 站点配置
├── sidebars.ts                         # 产品/版本作用域的侧边栏配置
└── node_modules/
```

### 2.5 `site/sidebars.ts` - 产品/版本侧边栏

侧边栏不是全站总目录，而是当前产品/版本的阅读目录。当前 Filament v4.x 使用独立的 `filamentV4Sidebar`：

```text
filamentV4Sidebar
├── 介绍
├── 资源
├── 组件
├── 表单
└── ...
```

执行规则：

- 左侧顶层只放当前产品/版本的章节分类，例如 `介绍`、`资源`、`表单`。
- 不在侧边栏中再包一层 `中文技术文档站`、`文档` 或 `Filament v4.x`。
- 同一个产品的不同版本各自使用独立 sidebar id，例如 `filamentV4Sidebar`、`filamentV5Sidebar`。
- 后续接入 Laravel 等新产品时，应新增独立 sidebar id，例如 `laravel12Sidebar`，不要把 Laravel 分类追加进 `filamentV4Sidebar`。

### 2.6 产品入口与版本切换

当前导航模型是：**首页按产品/框架聚合入口，版本在产品内部通过下拉切换**。

执行规则：

- 首页一张卡片代表一个产品或框架，例如 `Filament`，不为 `Filament v3.x`、`Filament v4.x`、`Filament v5.x` 分别创建并列卡片。
- 顶部导航的产品入口显示产品名，例如 `Filament`；版本选择由独立的版本下拉负责，例如 `v4.x`。
- 文档页路径仍然保留版本段，例如 `/docs/filament/v4.x/introduction/overview`，这样不同版本可以并存。
- 版本下拉使用 Docusaurus 内置 `dropdown` navbar item，默认跳转到对应版本的默认入口；如需官方文档那样保留当前相对页面，后续应单独引入经过验证的主题扩展或迁移到 Docusaurus 官方版本化结构。
- 产品、版本、默认入口、来源链接、sidebar id 等元数据集中维护在 `site/src/data/docsCatalog.ts`。

后续新增 Filament 新版本时，默认需要补齐：

```text
sources/filament/{version}/
content/filament/{version}/zh-cn/
site/docs/filament/{version}/
site/static/assets/filament/{version}/
site/sidebars.ts 中对应的 sidebar id
site/src/data/docsCatalog.ts 中对应的 version 条目
```

新增同一产品的新版本时，不新增首页产品卡片；新增全新产品时，才新增首页产品卡片和顶部产品入口。

## 4. 关键路径映射关系

这是最容易踩坑的地方，务必理解：

| 内容类型 | sources/ 路径 | site/ 路径 | 说明 |
|---------|--------------|-----------|------|
| 文档文件 | `sources/filament/v4.x/normalized/docs/...` | `site/docs/filament/v4.x/...` | 需要复制并修复路径 |
| 图片资源 | `sources/filament/v4.x/raw-assets/...` | `site/static/assets/filament/v4.x/...` | 已复制，路径不同 |

### 3.1 图片路径转换规则

| 原始路径（sources/ 中） | 正确路径（site/ 中） |
|------------------------|---------------------|
| `../../raw-assets/docs-assets/screenshots/...` | `/assets/filament/v4.x/screenshots/...` |
| `../../../raw-assets/docs-assets/screenshots/...` | `/assets/filament/v4.x/screenshots/...` |

**核心规则**：
- `sources/` 中的相对路径 → `site/` 中的绝对路径
- 前缀统一改为 `/assets/filament/v4.x/`
- 去掉路径中的 `docs-assets/` 层级

## 5. 翻译工作流中的目录操作

正确的翻译流程应该是：

```text
1. 读取源文件：sources/filament/v4.x/normalized/docs/...
2. 翻译内容：在内存中完成翻译
3. 存储翻译成果：content/filament/v4.x/zh-cn/docs/...（归档）
4. 部署到站点：site/docs/filament/v4.x/...（用户可见）
   └── 关键步骤：修复图片路径！
```

## 6. 常见错误

### ❌ 错误 1：直接复制不修复路径

```bash
# 错误！会保留相对路径导致图片加载失败
cp content/filament/v4.x/zh-cn/docs/01-introduction/01-overview.md \
   site/docs/filament/v4.x/introduction/overview.md
```

### ❌ 错误 2：以为 content/ 就是站点内容

`content/` 只是归档，不是站点实际读取的目录。

### ✅ 正确做法

复制后必须修复图片路径：

```bash
# 复制文件
cp content/... site/docs/...

# 修复图片路径（sed 示例）
sed -i 's|../../raw-assets/docs-assets/|/assets/filament/v4.x/|g' site/docs/...
sed -i 's|../../../raw-assets/docs-assets/|/assets/filament/v4.x/|g' site/docs/...
```
