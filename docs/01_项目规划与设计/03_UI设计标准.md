# UI 设计标准：Editorial Paper Docs

本文档定义“技术文档汉化工作台”的统一阅读界面标准。后续新增任意产品文档时，默认沿用本标准，除非项目文档中另行记录新的设计决策。

## 设计目标

- 以长文阅读、代码查阅和版本化维护为第一目标，不做营销型首页。
- 视觉气质接近纸张、书写纸、报刊专栏：温暖、安静、低干扰。
- 信息密度适中，适合连续阅读，也适合在侧栏中快速跳转。
- 所有产品文档共享同一套导航、正文、代码、表格和提示块样式。

## 视觉方向

命名为 `Editorial Paper Docs`。

核心特征：

- 背景使用暖纸色，不使用纯白大面积底色。
- 正文使用深墨色，链接使用克制的青绿色，状态或强调可使用少量铁锈红。
- 页面可以有细微纸张纹理和细线分隔，但不使用装饰性渐变球、漂浮卡片、强烈阴影或炫技动画。
- 圆角控制在 8px 以内，避免过度柔软的 SaaS 卡片感。
- 首页是文档入口和项目状态，不是品牌落地页。

## 色彩令牌

基础色：

- `paper`: `#f4efe3`，页面主背景。
- `paper-soft`: `#fbf7ed`，正文表面和浅色区域。
- `paper-strong`: `#e5d7bd`，边框、分割线和表格线。
- `ink`: `#26231d`，正文主文字。
- `ink-muted`: `#6c6254`，辅助文字。
- `teal`: `#0f766e`，主链接、主按钮和当前项。
- `rust`: `#a44f2d`，谨慎用于状态、版本或警示强调。

暗色模式保留，但不是首要设计目标。暗色模式应延续“纸张阅读”的低对比暖黑风格，避免纯黑背景和高饱和霓虹色。

## 字体与排版

- 中文正文优先选择屏幕可读的中文字体栈：`LXGW WenKai Screen`、`Noto Serif SC`、`Noto Sans SC`、`Microsoft YaHei`、系统字体。
- 英文和数字不单独追求装饰性字体，优先保证代码、路径和 API 名称清晰。
- 正文行高建议 `1.85` 左右。
- 正文阅读宽度控制在约 `760px` 到 `820px`，不要让长行横跨整个屏幕。
- 标题层级清晰，但不使用夸张 hero 字号进入文档正文。
- 字距保持默认，不使用负字距。

## 页面结构

- 顶部导航固定为轻量项目导航：站点名、文档入口、源文档链接。
- 左侧边栏用于产品、版本和章节目录，不做视觉卡片化。
- 右侧目录用于当前页面锚点，突出当前阅读位置。
- 首页需要展示文档集合、版本状态、来源和维护阶段。
- 页面区块使用全宽背景或自然留白，不把区块包进层层卡片。

## 正文内容标准

- 每篇文档的正文应优先展示技术内容，不添加解释 UI 功能的可见提示文案。
- 外部来源、版本、翻译状态等元信息应保持简短，避免干扰正文。
- 图片用于说明真实产品界面或技术状态，边框应轻，阴影应浅。
- 表格要适合扫描：细边框、浅表头、充足单元格内边距。
- 链接需要可辨识，但不使用大面积高饱和色。

## 代码与技术内容

- 行内代码使用浅纸色底、细边框和等宽字体。
- 代码块背景应偏暖浅色，不使用强烈黑色代码块作为默认阅读体验。
- 代码块需要横向滚动稳定，不因为长路径撑破页面。
- 命令、路径、类名、配置项统一用代码样式表达。

## 提示块与状态

- Docusaurus admonition 保持可识别，但视觉上要像报刊注释框。
- `note` 和 `tip` 使用青绿色系。
- `warning` 和 `danger` 使用铁锈红或暖橙色系。
- 提示块不使用厚重阴影，也不使用高饱和背景。

## 响应式规则

- 移动端优先保证正文可读和导航可用。
- 按钮、入口卡片、状态信息需要自然换行，不允许文字溢出。
- 固定格式元素要有稳定尺寸或响应式约束，避免 hover、标签或长文本导致布局跳动。
- 不使用随视口宽度线性缩放的正文文字。

## 新文档接入规则

新增产品或版本文档时，需要遵守：

- 首页入口复用同一产品列表样式。
- 版本状态使用统一短标签，例如“样板接入”“翻译中”“校对中”“已归档”。
- 源文档链接保留在产品入口、manifest 或文档元数据中。
- 不为单个产品单独引入大面积品牌色，除非先更新本设计标准。

## 实施范围

当前 Docusaurus 实施以这些文件为主：

- `site/src/css/custom.css`：全站主题令牌、文档正文、导航、代码块、表格和提示块。
- `site/src/pages/index.tsx`：文档工作台首页结构。
- `site/src/pages/index.module.css`：首页布局和入口样式。
- `site/docusaurus.config.ts`：导航、页脚、主题配置。

原则上优先通过主题 CSS 和轻量页面组件完成，不对 Docusaurus 主题做大规模 swizzle，保持后续升级简单。
