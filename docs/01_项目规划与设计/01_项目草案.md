# 01. 项目草案

**项目名**: 技术文档汉化工作台  
**目录名**: `tech-docs-zh`  
**创建日期**: 2026-05-16  
**当前状态**: 草案已建立，等待首个文档源接入

## 1. 项目背景

很多技术产品的官方文档只提供英文，或中文内容来自浏览器机翻，术语不稳定、代码上下文容易误译、示例说明不够自然。本项目用于把这些英文技术文档整理成可维护的中文版本。

首批可作为入口的产品包括：

- Filament
- Laravel
- daisyUI
- Tailwind CSS
- 其他后续需要长期查阅的英文技术文档

## 2. 目标

- 建立一个本地可运行的中文技术文档站。
- 首页按产品分入口，例如 `Filament`、`Laravel`、`daisyUI`、`Tailwind CSS`。
- 每个产品入口下按版本组织文档，例如 `Filament v3.x`、`v4.x`、`v5.x`。
- 页面结构尽量贴近官方文档的阅读路径：左侧目录、正文、页内标题导航、版本选择、搜索。
- 每篇译文保留来源信息，方便回查英文原文和版本差异。
- 汉化时优先保证技术准确、术语一致、中文自然，而不是逐字直译。

## 3. 非目标

- 当前阶段不做线上发布。
- 当前阶段不做用户系统、权限、后台管理、数据库。
- 不完整复制官方站点 UI、品牌视觉或受版权保护的资源。
- 不把浏览器机翻结果当作最终内容。
- 不在未确认授权、许可或使用条款的前提下公开发布整站镜像。

## 4. 首期产品形态

首期建议做成本地静态文档站：

- 开发地址固定使用 `127.0.0.1:48763`。
- 文档内容用 Markdown/MDX 维护。
- 每篇文档通过 frontmatter 记录产品、版本、来源、翻译状态。
- 生成站点时自动获得目录、代码高亮、全文搜索、版本下拉。

后台管理系统暂不建设。只有当后续出现多人协作、翻译任务流、术语审批、审核记录、权限分级时，才引入 Laravel + Filament 做内部管理端。

## 5. 内容组织草案

项目级目录先分成三层：

```text
sources/
└── filament/
    └── v4.x/
        ├── raw/          # 官方原文快照
        ├── normalized/   # 清洗后的 Markdown/MDX
        └── manifest.yml  # 来源、采集时间、许可、校验信息

content/
└── filament/
    └── v4.x/
        └── zh-cn/        # 汉化后的 Markdown/MDX
```

后续接入 Docusaurus 时，可再把 `content/` 转换或同步到 Docusaurus 的 `docs/`、`versioned_docs/`、`versioned_sidebars/` 结构。

## 6. 单篇文档元数据草案

```yaml
---
title: 安装
product: filament
version: v4.x
source:
  url: https://filamentphp.com/docs
  retrieved_at: 2026-05-16
  license: 待确认
translation:
  status: draft
  reviewer: null
  updated_at: 2026-05-16
---
```

建议的翻译状态：

- `raw`: 仅保存原文。
- `normalized`: 已清洗为可翻译格式。
- `draft`: 已生成中文初稿。
- `reviewed`: 已人工校对。
- `synced`: 已根据官方新版本同步。

## 7. 首期实施顺序

1. 先选一个产品和一个版本做样板，例如 `Filament v4.x`。
2. 确认官方文档来源、源码仓库、许可和资源路径。
3. 采集 3 到 5 篇代表性页面，覆盖普通说明、代码块、图片、组件示例。
4. 建立术语表，例如 `resource`、`panel`、`action`、`policy` 是否翻译。
5. 生成中文 MDX，并本地构建文档站。
6. 再扩展到整套版本和其他产品。
