# 05. 框架入口与版本下拉调整记录

**日期**: 2026-05-17  
**阶段**: 导航模型调整

## 1. 需求背景

原实现把 `Filament v4.x` 直接作为首页卡片和顶部文档入口。后续如果接入 `Filament v3.x`、`v5.x`，这种方式会让同一框架的多个版本在首页并列出现，入口逐渐膨胀。

本阶段将导航模型调整为：一个框架一个入口，框架内部通过版本下拉切换。

## 2. 关联提交

当前尚未形成独立提交。本记录依据 2026-05-17 工作区中 `site/src/data/docsCatalog.ts`、`site/src/pages/index.tsx`、`site/docusaurus.config.ts` 和项目文档变更编写。

## 3. 实现要点

- 新增 `site/src/data/docsCatalog.ts`，集中维护产品、版本、默认入口、来源链接和 sidebar id。
- 首页从“版本卡片”调整为“产品/框架卡片”，同一产品的版本显示在卡片内部。
- 顶部导航保留 `Filament` 产品入口，并新增 Docusaurus 内置 `dropdown` 版本下拉用于切换版本。
- 版本下拉当前跳转到各版本默认入口；如需保留当前相对页面，后续可单独验证主题扩展或迁移到 Docusaurus 官方版本化结构。
- 同步项目规划、目录结构、UI 标准、翻译指南和校对流程，明确新增同一产品版本时不再新增首页产品卡片。

## 4. 验证收口

- `npm run typecheck` 已通过。
- `npm run build` 已通过并生成静态站点。
- 构建仍提示既有 broken links / anchors，原因是 Filament v4.x 仍处于分批翻译接入阶段，部分目标页面和锚点尚未接入；本次导航模型调整没有新增构建阻断错误。

## 5. 本阶段收益

同一框架的版本入口被收口到框架内部，首页可以长期保持按产品组织。后续新增 Filament 新版本时，主要补版本目录、sidebar 和 `docsCatalog` 版本条目即可。
